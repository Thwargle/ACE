# Loading, terrain descent, and movement packet corrections

Shared client source remains in `Unreal/Plugins/ACEClient`; Quest consumes it
through `Quest/Sync-ClientSource.ps1`.

- Start the portal transition on EnteringWorld, before the server's character
  handshake finishes. Prepare the real portal mesh during character selection,
  preserve it on entry, and submit a portal frame before destination installs.
- Remove synchronous terrain/interior construction from the enter-world network
  callback. Process portal terrain installs per frame with a 2 ms soft budget;
  warm gameplay UI textures in batches of at most eight / 2 ms. Individual
  resource installs can exceed that soft budget; headset timing still needs a
  live check. Editor background throttling no longer throttles an active VR rig.
- Surface interiors continue loading their exterior. The regression uses the
  reported Sanctuary arrival, cell F4180104 at 36.90, 48.70, 169.805. Dungeons
  remain excluded from outdoor streaming. Physical support gates arrival;
  visible terrain, scenery, and HUD readiness still gate the reveal.
- Terrain height queries can return their actual triangle normal. Ground
  fallbacks reject unwalkable slopes, and steep airborne contacts preserve
  gravity in desktop and VR. VR's below-terrain recovery no longer resets a
  cliff slide to a fresh fall each frame.
- Point uses the supported PointState emote instead of the Point transition.
  The server normalizes a filtered action list's count and checks the actual
  list before indexing, preventing the reported MoveToState exception.

## Validation

- Windows editor and Android Development client compile successfully.
- Client regressions passed: LoadingTransition (including Sanctuary), PortalSpace
  (rendered captures inspected), TerrainHeight, LedgeStairs, StairCeiling, and
  ChatInputAndCommands. The cliff controller test covers desktop and VR at
  20/90 Hz: approximately 4.0 m descent in one second, retaining downward speed.
- Server RawMotionStateTests passes rejected-only and mixed accepted/rejected
  commands, checking normalized counts and alignment of the following field.
- The broader WorldEntry test exposes an existing bench step-over failure with
  the fixture's game-instance world correctly bound. Its eight traversal cases
  fail identically with the original HEAD PlayerTick implementation; this is a
  separate outstanding collision issue. Other assertions in that test pass.
- Logs/captures are under `Unreal/Saved/Loading-*`,
  `Unreal/Saved/MovementBaseline`, and `Quest/Logs/Loading-*` (ignored output).
- Updated server binaries are staged in `Unreal/Saved/VRServer`. This work does
  not restart the live shard or deploy the Quest APK. On-device loading comfort
  and the exact photographed cliff still need a gameplay check.
