# Quest v60: missile release, river landing, and launcher controls

## Changes

- The local shard was still running the September 17 server binary. Its missile
  handler required a draw duration for every weapon except crossbows, rejecting
  atlatl and thrown-item trigger clicks. The current server has been published,
  gracefully restarted, and verified against the staged binary. Only bows require
  a physical draw. Rejections distinguish missing stance from insufficient draw.
- Bow releases now honor the same server recovery timer as other missiles.
  Atlatl/thrown sends have connection-failure feedback and diagnostic logging.
  Weapon placement and aiming transforms are unchanged.
- Desktop water jumps now use the outdoor DAT floor bound already used by VR.
  The rendered water sheet remains non-blocking; the submerged walking surface
  is the landing plane. This avoids falling beneath the terrain after a jump.
- The account launcher includes Quit and a footer version label. Quest packaging
  refuses a mismatch between the APK version and the displayed build version.
- This package also includes the previously validated mouse inversion, desktop
  UI scale, FPS overlay, rounded number-free enemy health bar, wall sliding, and
  deliberate two-hand-use changes.

## Validation

- 17 VR protocol/release server tests passed, plus 5 projectile integration cases:
  actual bow, crossbow and atlatl ammunition, untargeted arrows, and thrown items.
- Client controller tests cover both handedness settings, atlatl style inference
  from public metadata, incompatible ammunition, instant trigger firing, and
  bow/atlatl recovery suppression.
- The initial river regression reproduced desktop fall-through below the water
  bed. Final tests passed 80 jump scenarios at 90 and 20 Hz in desktop and VR
  movement modes: Rithwic, DC56001F, the reported A8B40008 Holtburg bank, and the
  adjacent A7B4 river. Stationary and running jumps include a landblock crossing.
- Final mobile-renderer suite passed all six groups: Launcher.ResponsiveUI,
  RetailParity.AcademyCorners, RetailParity.LedgeStairs, VR.Protocol,
  VR.RigAndMenus, and VR.StairCeiling. Launcher renders inspected at headset-panel
  size. Test reports are in ignored Unreal/Saved/Automation/MissileRiver60Mobile.
- Editor, Windows, and Android packaging succeeded. The Windows cook regenerated
  runtime materials, which were synchronized and repackaged for the public Quest
  release. Shared Quest source check: zero differences. Installed package reports
  versionCode 60 and matches the final release APK SHA256:
  3C02CCE4B4099AF4801470E0D5B0C5F10844D8F3EAF879E90B25077A5388DC08.
- The packaged Windows game passed seven suites: Launcher.ResponsiveUI,
  Packaging.LandscapeTextureFidelity, Packaging.Materials,
  RetailParity.AcademyCorners, VR.Protocol, VR.RigAndMenus, and VR.StairCeiling.
  Four expected protocol-rejection warnings occurred in the negative cases;
  there were zero failed tests. Report: Unreal/Saved/Automation/v60Packaged.
