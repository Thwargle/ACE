# AC:VR v62 / AC:Unreal 2026.09.22.68

Published as public release v62 on thwargle.com/unreal/ and thwargle.com/unreal-vr/.

## Portal streaming and memory

- The user corrected the crash location to **Obsidian Rim**, not Singularity Bore.
  The original capture contains a kernel out-of-memory kill, without an Unreal
  exception stack. v61 loaded Rim once, but the repeated portal route terminated
  again under heavy memory pressure: Android reported 5.26 GiB total PSS including
  2.10 GiB swapped, with 3.11 GiB attributed to graphics. The second recording did
  not contain a new kernel OOM message, so its exact termination cause is unconfirmed.
- Release departed outdoor meshes on entry to an enclosed dungeon and release
  old room meshes even when transition cleanup already removed their actors.
- Discard cancelled background results. Old-generation completions cannot
  remove current requests or requeue rooms from the departed area.
- Limit concurrent room builders to two on native Quest and four on Windows.
- Remove a redundant copy of the complete parsed dungeon environment per worker.
- Before loading another destination, retire the old actors, discard distant CPU
  meshes, request garbage collection with incremental resource destruction, and
  poll a render/RHI fence without blocking the portal frame loop. This prevents
  rapid portals from accumulating terrain textures for the normal 60-second GC
  interval. Nearby destination CPU caches remain reusable.
- Regressions cover the Bore's 172 arrival cells at 0x02910388, cancelled worker
  callbacks, and actual terrain resources from the recorded Caul → Obsidian Rim
  (0x2E43000C) → town → Caul → Rim route. All departed terrain texture weak references
  expire before the next allocation.
- v62 is installed and verified on the local Quest 3. The native recording contains
  one successful login and seven completed teleports; the user confirmed repeated
  Obsidian Rim trips look correct. Each departure released all old terrain textures
  (394.7–768.1 MiB) before destination allocation. Incremental retirement took
  0.423–0.722 seconds across multiple submitted portal frames.
- Across 27 samples at five-second intervals, v62's maximum Android total PSS was
  2,797,142 KiB (2.67 GiB), versus 5,519,297 KiB (5.26 GiB) in the failed v61 run.
  Maximum RSS was 2,934,112 KiB; swap stayed at 216 KiB, versus approximately
  2.10 GiB of swap in v61. These are sampled peaks from the recorded routes,
  not allocation-level peaks or a controlled same-view FPS benchmark.
- Later outdoor frame samples remain around 59–66 FPS, below the 90 FPS target.
  This validates portal resource retirement, not completion of performance work.

## Performance and textures

- Reuse the UI name index until tree membership, names or ordering change;
  continue evaluating visibility on each lookup.
- Cache outdoor admission landblock keys until the area/radius changes, and
  avoid repeated ceiling visibility updates when the value is unchanged.
- Use the fast lossless LZ4 encoder for terrain mip backing data. UE's
  `NAME_LZ4` wrapper uses the high-compression encoder even with `BiasSpeed`.
  Eight actual Shoushi blends, four repetitions: compression 1010.59 ms to
  37.50 ms; packed bytes 68.69 MiB to 70.13 MiB. These are desktop worker
  microbenchmark results, not a measured Quest frame-rate improvement.
- Persist complete prepared mip chains so cache hits avoid repeating mip
  generation and compression. Validate sizes, schema, fingerprint and CRC;
  use unique temporary filenames and atomic replacement.
- UI panel/chrome textures keep their authored size with a single bilinear mip.
  World terrain/scenery retain mipmaps and full-resolution source textures.

## Gameplay and UI

- Resolve simultaneous body contacts with the floor and neighbouring surfaces
  together, including near-touching neighbours at large world coordinates.
  The actual Eiichi/lifestone shapes pass all 28 approach/retreat probes;
  training-dungeon corner and interior-streaming regressions also pass.
- Reduce the VR enemy meter from 512x64 to 512x40; zero-health events do not
  allocate meters and immediately hide existing ones. Corpse meters stay hidden.
- Use retail minimap pixel masks, colors, range and selected square. Pick the
  nearest blip within the retail click tolerance. Use original DAT arrow art
  for offscreen selections. Preserve fellowship and monarch marker differences.
- Keep oversized settings windows and Apply accessible after desktop DPI changes.
  The resize test restores viewport geometry before restoring window positions.
